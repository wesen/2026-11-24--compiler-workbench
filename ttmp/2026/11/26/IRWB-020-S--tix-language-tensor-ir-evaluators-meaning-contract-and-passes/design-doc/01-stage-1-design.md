# Stage 1 design: Tix on IR Workbench v6

**Decision requested:** Approve the supported Tix subset, the sampled gate, and the narrow synchronous framework entry point below. This turn changes documentation only.

## 1. Front end and supported domain

Tix programs are nonempty lists of independent functions. Function calls in expressions are only the specified builtins. Tensors have positive rank and positive safe-integer extents and must fit in row-major typed arrays. Calls to `runTix` provide row-major `Float32Array` or `Float64Array` buffers of the exact shape and length for each parameter. Values must be finite and, for f32 execution, still finite after conversion to f32. Evaluation can produce nonfinite results. `compileTix`, `runTix`, and `optimizeTix` are synchronous exports from `dist/tensor/index.js` with the ticket's signatures; `runTix` defaults to f32.

- **Parsing.** A hand-written lexer and precedence parser preserve 1-based `line:col` on tokens and AST nodes. Honor `//`, unary minus, left associativity of binary operators, and delimiter-bounded, greedy reduction bodies. E.g. `sum(d) x[i,d] / D` reduces the division; `(sum(d) x[i,d]) / D` divides afterward. Distinguish `max` forms by inspecting the parenthesized arguments: a comma-separated bare-name list followed by a body can be a reduction; two scalar expressions are a call. If both a shape-name call followed by binary `-` and a reduction with a negative body are possible, prefer the call; `max(i,j) (-expr)` spells a negative reduction body explicitly. `sum` is always a reduction; `min` is always a call. Accept finite decimal literals including exponents. This parser is smaller than adding a grammar generator and keeps the greedy boundary explicit.
- **Shapes.** Parameter axes are positive integer constants or bare shape names. Their first occurrences bind concrete sizes; repeated occurrences must match. Return types and statement annotations also allow sums and differences of those names and integer constants, e.g. `H - 2`. Tensor subscripts support the same affine fragment over in-scope indices, e.g. `y + dy`. Normalize to a constant and sorted integer coefficients, and compare normalized extents. Reject non-affine syntax and out-of-subset parameter-axis expressions rather than adding a solver. Shape names in scalar expressions resolve against the signature, not the index environment.
- **Bind and check.** Check functions and each function's statements in source order. Resolve loads only to parameters or previously defined tensors. Reject duplicate function/parameter/tensor names, duplicate binders in one list, unknown names, wrong ranks and incompatible return or index extents. Each LHS or reduction binder gets a unique ID. Infer its extent from every syntactically bare use in a tensor axis of its scope (including uses in nested expressions that do not shadow it). These extents must agree. An LHS binder used only in affine subscripts needs a declared axis; any declared axis must also agree with bare uses. Reject missing extents, including an affine-only reduction binder with no bare use. Reduction bodies can use the enclosing binders but do not export their own. There is no tensor-level broadcasting or reassignment; omitting an enclosing LHS index from an individual load is fine if the statement determines that index elsewhere.
- **Bounds.** After inference, use each index's range `[0, extent-1]` to form the symbolic minimum and maximum of each affine subscript, taking the appropriate endpoint for each coefficient's sign. Prove `min >= 0` and `axisExtent - 1 - max >= 0` by simplifying each affine difference and checking nonnegativity under shape names `>= 1` (substitute `S = 1 + S'`, check nonnegative constant and coefficients). Reject an unproved access at compile time. For conv2d with a constant `3×3` kernel, `y` has extent `H-2` and `dy` has extent `3`, so `y+dy` has extrema `0` and `H-1`. This test suffices without a general affine inequality solver. Check positivity of constant extents at compile time; shape-dependent extent positivity and consistency with concrete arguments are checked at `runTix` entry, before allocating intermediates or evaluating. E.g. `H=2` cannot specialize a convolution with extent `H-2`. Errors name the offending token or axis/parameter and include its `line:col`. Neither an uninferable extent nor a provable source-level mismatch is deferred to execution.

## 2. Native v6 artifact and evaluators

Use a finite-JSON `tensor.tix@1` artifact. The payload is an ordered list of functions with signatures, ordered single-assignment tensor definitions, and return IDs. Each definition stores its checked shape, bound axes, and a scalar expression tree. Expression nodes are literal, shape lookup, affine load of a tensor ID, scalar op/builtin, or reduction. A reduction contains ordered binders with explicit extents, body, operator, and schedule (`serial` or, for unary `sum` only, `blocked` with block size). Locations are diagnostic metadata. Scope is explicit in binder IDs; evaluation does not consult source spellings. Represent numbers as finite unsigned literal magnitudes plus an explicit negation node, so v6's JSON canonicalization of `-0` does not lose Tix's negative-zero behavior. The `max` accumulator's `-Infinity` is evaluator state, not artifact data.

`defineIR` and `defineAdapter` share a native validator for the payload, including scopes, shapes, access bounds, and the reduction schedule. A browsing projection exposes functions, parameters, statements, expressions and binders; containment edges encode order, dependency edges link loads/returns to tensor definitions, and binding edges link subscript occurrences to binder IDs. Rewrites use immutable native results, with stable IDs for retained entities, fresh IDs for inserted trees and correspondence for origins of cloned or removed code. Both rewrites can declare writes confined to statement/expression/binder entities and affected containment, dependency and binding relations. The signature is part of the checked interface. Use `createIRArtifact`/`openIR` for identity and graph validation. Do not implement graph-to-native rebuild: expression-tree substitution and schedule updates are simpler natively, and no generic edit is needed. An AST with unresolved shapes would force each consumer to infer them again; a CFG would hide the tensor axes and reduction structure these passes need. An ordered definition, explicit axis extents, and explicit reduction schedules suffice for eventual loop-level lowering.

Use one evaluator with two arithmetic policies. At entry, bind/check shapes, compute extents/row-major strides and read the inputs at the requested precision. Execute statements in source order, enumerating LHS coordinates lexicographically and evaluating loads/scalar expressions. In f32 use `Math.fround` at inputs, literals, shape values, unary/binary operators, builtin returns (`Math.exp/log/sqrt/tanh/max/min`) and each reduction fold step. Use `+0` and `-Infinity` as the respective identities for `sum` and `max`; the first listed reduction axis is outermost. Store results in `Float32Array`. In f64 use JS double operations without f32 conversions and `Float64Array`, with the same traversal, builtins and identities. Using a shared traversal makes f64 a precision reference rather than a second interpreter; hand-computed non-square fixtures check traversal independently. The tolerance gate always evaluates the **original serial artifact** in f64, never the candidate in f64.

## 3. Meaning contract

**Domain.** All functions of the original artifact. For each function, propose uniform shape assignments `1, B, B+1, 2B, 2B+1` (`B = 2`) and cyclic shifts of that vector across shape names, in stable signature order. The first group covers singleton, one block, a partial block, two full blocks, and two blocks plus a tail; the second catches axis swaps that square tensors hide. Honor constant axes and discard duplicate, invalid or excessive-work specializations using the same shape checker as `runTix`. Cap sampled work per statement/reduction path at `5^6` loop-body visits (product of output and reduction extents): at the largest sampled shape even conv2d needs only `5×5×3×3×5×3×3 = 10,125` visits. This bounds the sampling domain, not the public evaluator's shape semantics. If a function has no usable case, a changed candidate cannot pass the gate.

For each usable shape use one case per profile: zeros (including `-0`), ones (detect dropped terms), a sign-varying seeded uniform sample in `[-1,1]` (break symmetry), and the periodic sequence `[1,0,2^-24,2^-24,0]` in row-major order (surface reassociation). Convert all case inputs to f32 before passing the same input data to either evaluator, so the tolerance measures arithmetic rather than different inputs. Use v6 `seededRandom` at its default differential seed (`1`) and record that seed. Case evidence records function, concrete shapes and profile/seed or fixed values sufficient to reconstruct the case, plus the first differing coordinate and bits or numerical error. Signature drift (function/parameter names, shape axes or result type) fails independently of numerical outcomes. This structured set is smaller and more targeted than many unconstrained random draws; there is no guarantee on shapes or values not sampled.

**Observation.** Compare the return shape and every element at its row-major position. No reduction or checksum of errors; it could hide a wrong output position. Return observations use typed arrays locally. Encode nonfinite values or bit patterns as strings in evidence so v6 records remain finite JSON.

**Relations** (two versioned `differential()` invariants over the same tensor IR ports):

- **Exact:** run both sides in f32 and compare the `Uint32Array` views of the result. Compare stored bits, including the sign of zero and any NaN representation observed on Node; the language does not specify portable NaN payload bits.
- **Tolerant:** compare each candidate f32 cell `c` against the original f64 cell `r`. Require both finite and `abs(c - r) <= 2^-19 + 2^-21 * abs(r)`. Unit roundoff is `u = 2^-24`. For a direct sum of up to five unit-scale, pre-rounded terms, each term passes through at most five rounded additions (two within a block and up to three between blocks). The usual absolute error bound `γ₅ * Σ|term|`, where `γ₅ = 5u/(1-5u)`, is at most about `1.50e-6` there; `2^-19 ≈ 1.91e-6` covers that near cancellation. For same-sign terms, `Σ|term| = |r|`, so `2^-21 ≈ 4.77e-7` exceeds `γ₅` and lets the allowance scale. This is a measured-on-cases gate, not a bound for arbitrary chains of operations, cancellation at larger scale or ill-conditioned nonlinear expressions. Reject if the observed error exceeds the allowance, even for a structurally correct split. An absolute-only rule ignores scale, and a relative-only rule fails near zero.

## 4. Passes and pipeline

- **`inline`.** Find a non-returned tensor defined by a pointwise statement (no reduction in its RHS) with exactly one syntactic load across the function. Replace that load in its consumer by a copy of the RHS with producer axes substituted by the load's affine subscripts; compose the affines of nested loads. Use binder IDs so insertion inside a reduction cannot capture an index. Retain every arithmetic node and its rounding; remove the now-unused producer. If a proposed substitution cannot be validated within the supported bounds fragment, leave it alone. A first implementation visits original definitions in source order and updates use counts for the current function after each accepted local substitution; it does not do algebraic simplification or a separate dead-tensor pass.
- **`split-sum`.** Replace a serial `sum` with exactly one bound axis by a blocked sum. `B=2` is the smallest block width with a distinct within-block accumulation and a simple witness on five entries. For extent `D`, the outer sum runs over `ceil(D/B)` blocks in order; inner sum covers the original indices `[b*B, min((b+1)*B,D))` in order and resets to `+0` for each block. Both accumulation levels round after every step. Do not change the expression body, multidimensional reductions, or `max`; do not split an already blocked root again. A schedule variant is smaller than introducing source syntax or artificial rectangular axes/padding for the incomplete block.
- **API / publication.** `TixProgram` holds the current artifact, immutable compile origin, and the relation established for the current revision. The origin survives across `optimizeTix` calls. Run requested passes in order. `split-sum` checks tolerance directly against the origin. `inline` checks exact f32 equality against its immediate input and also checks the candidate against the origin with the current revision's relation (exact before any accepted split; tolerant after). When both exact comparisons have the same baseline, run them once. This keeps `inline` bit-identical as a step without requiring it to undo an earlier valid reassociation, and prevents an approximate error budget from being renewed at each pass. A sampled rejection yields `{pass, accepted: false}` and leaves the current revision usable for subsequent passes. An applicable no-change step is accepted as identity; no new revision is produced. The output of an unchecked kernel is never returned. The API does not expose mutant names; tests can use internal pass specifications and override the relation on the exact same rewrite.

**Decisive checks:** Use `fn total(x: f32[1,N]): f32[1] { y[i] = sum(k) x[i,k]; return y; }`. On `N=5` with the periodic profile above, serial f32 gives `0x3f800000`, blocked f32 gives `0x3f800001`, and serial f64 is exactly `1 + 2^-23`. A Node 24 probe of those folds confirmed all three. Assert that the exact gate rejects the *same* changed blocked artifact the tolerant gate accepts. A wrong split variant doubles each block's contribution (encode that as `2 * blockedSum`, a valid IR change); on five ones it gives `10` versus `5`, so tolerant checking rejects. Separately, the correct blocked rewrite on five ones must give `5`, not `4` (lost odd tail). For `inline`, use a single-use pointwise producer with e.g. `x[i] + 1` and a consumer that multiplies it; a mutant using `x[i] - 1` in its substitution must be rejected by exact checking. Check evidence for the expected disagreement, not incidental validation errors.

## 5. Proposed framework changes (complete inventory)

Typed uses `defineIR`/`createIRArtifact`, `definePass`, `differential()`, and `applyPass` with `AnalysisManager.verifyTransformation`, passing a separate `origin` port. The adapter, artifact and case comparison APIs already fit tensors. In particular `DifferentialSpec.run(side,...)` can pick a different evaluator on each side, and `compare` defines the relation; no f32/f64 or tolerance policy belongs in v6. The mismatch is execution: `applyPass` and `AnalysisManager` are async, and `applyPass` eagerly creates an edit draft even for native results (`Edit` requires `adapter.rebuild`). The fixed synchronous API makes the first mismatch unavoidable. Implement the following as one additive native + sampled entry point:

| Framework area | Proposed change and reason |
| --- | --- |
| `passes/define-pass.ts` and `passes/index.ts` | Add `applySampledNativePassSync`, accepting a versioned native-only pass spec (same id/version, IR/adapter, writes, `defineTransformation` contract; `run({before, view, params})` returns a native result or identity). No edit or caller-supplied store; only return the candidate after checking. Extract the existing native candidate creation, projection diff, correspondence and write checks for reuse by both pass entry points, preserving the existing async path's behavior. The new path returns the artifact/change fields and sampled check evidence; a rejected check reports the failing invariant and witness. |
| `contracts/differential.ts` | Add a synchronous entry for an existing `differential()` invariant; get its registered spec, reject async delegation, and call the same `runDifferential` and evidence-to-result helper used by `differential().check`. Do not implement a second checker or silently ignore `decide`. |
| `contracts/definitions.ts` and `contracts/analysis-manager.ts` | Share existing named-port validation and relational binding selection with the new entry point, keeping snapshot/type/revision checks. The synchronous runner takes a pure `defineTransformation` whose only clauses are one or more `ensures` of synchronous differential invariants. Require those clauses; reject unsupported clauses before running rather than silently ignoring them. No analysis manager, tracked dependencies, effects, transactions, arbitrary invariant callbacks, async bodies or cache acceptance in this path. Keep the async manager and existing pass/strategy APIs unchanged. |
| `contracts/README.md` | Document the v6 sampled entry and its restrictions. |

A tensor-only rewrite loop calling `runDifferential` directly is shorter initially, but would duplicate pass structural checks and leave an avoidable framework gap. Making all of `AnalysisManager` synchronous would disrupt Typed's workers and cover capabilities this stage does not need. Reuse the existing synchronous checking kernel and native structural preparation instead. No changes to `core`, `ir`, `dataflow`, or `strategy`: no CFG analyses, editable projection, or orchestration DSL are needed for a caller-provided list of two passes. The existing strategy bridge remains async.

## 6. Corpus and validation after review

| `corpus/tensor/<name>/main.tix` | Kernel and independent fixture |
| --- | --- |
| `matmul` | `A[M,K]·B[K,N]`; non-square hand-computed product. |
| `softmax` | Row max, shifted exp, row sum, division; large equal logits and nonuniform rows. |
| `layernorm` | Row mean and variance, positive literal eps inside sqrt, then elementwise gamma and beta; constant row returns beta, plus a nonconstant row. |
| `attention` | One head: scaled `QKᵀ`, max-shifted row softmax, and multiplication by `V`; different query/key lengths and an equal-score case with known output. |
| `mlp` | Two affine contractions with biases and tanh-GELU between them; rectangular fixture checking bias and activation placement. |
| `conv2d` | NCHW, weights `[O,C,3,3]`, output `[N,O,H-2,W-2]`, stride 1, no padding; asymmetric spatial axes and channels, including a corner impulse. |

Implement front end/IR and evaluator first, then the sync framework delta and passes, then complete corpus checks. In `tests/tensor/` exercise the built public API, first-line and multiline diagnostics, both `max` forms, greedy reductions and parentheses, indexing and shape-binding errors, negative zero and intermediate f32 rounding, and lexicographic multi-index accumulation. Run every corpus kernel in both precisions against independent expected results; optimize representative kernels and verify output and the changed IR. Contract tests check exact/tolerant verdicts, empty per-function sampling, partial blocks, mutants, and mixed pipeline order across multiple API calls. Framework tests check an accepted native pass, disallowed writes, malformed ports/artifacts, unsupported sync contracts/async work, and that the same invariant gives the same verdict and evidence through the async path.

Validation commands: `npm run build`; `node --test tests/tensor/*.test.mjs`; `node --test tests/framework/`; `node --test tests/typed/{passes,inline,meaning-memo,parallel,strategies}.test.mjs` (pass preparation/contract checks, baseline reuse, worker-backed meaning, strategy bridge). If spawning Node is blocked by sandbox EPERM, request escalation for that command. Record actual framework edits and any deviation from this proposal in the diary. No implementation or compiler test claims at design review.

- CUDA lowering and GPU runs, fusion, contraction tiling and attention-specific rewrites belong to later stages.
