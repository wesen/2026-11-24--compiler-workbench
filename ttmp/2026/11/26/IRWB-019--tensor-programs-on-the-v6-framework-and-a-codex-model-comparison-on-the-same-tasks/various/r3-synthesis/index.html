IR Workbench · IRWB-019 · round R3 · synthesis

What forty implementations say about the framework

Four agents reviewed the IR framework against two compilers (Typed to RV32, Tix to CUDA) and 31 unmerged implementations: Sol and Astra (OpenAI Codex), Opus and Fable (Claude). This page verifies their claims with probes, merges their proposals into one target architecture and one standard library, and orders a migration.

Verdict
  1. The outer shell held. Content-addressed revisions, adapters and projections, the contract vocabulary, revision-exact analysis caching, the batched differential and the strategy plan language carried both domains and every cell.
  2. The inner model of a transformation did not. A pass is an endomorphism. Its record is a diff. "Checked" is one word. Acceptance is spread over two runners and several publication points. Independent agents routed around each of these in the same few shapes.
  3. The coordinator was wrong about F27. Tix passes run in strategy plans today. They lose the meaning gate, and the bridge's existing contract option restores it without a framework change.
  4. v7 has six core concepts: a typed transformation with one lifecycle; a derivation written by the producer; evidence as relation × method × scope; staged publication; one runner with two drivers; decisions as data. A standard library of about twenty primitives sits below them.
  5. First moves: honest evidence, atomic publication, Tix plans through the bridge contract, then one runner.

The target architecture

The core knows nothing about programs. The standard library holds algorithms over one shape each (a graph, a lattice, terms, affine forms, binary32) and registers with the core only through optional wrappers. Domains supply semantics: evaluators, native transactions, emitters, measured constants.

K6 · Decisions as data split one signature

Untrusted decide returns a plan; a small eligible(plan) decides legality; prepare applies it. Fusion, schedules, binding-time divisions and guarded rewrites are instances.

Plus staged choice: a launch-time variant with its guard, so the differential's arms are derived.

How they got there →

Kept out of the core on purpose: graph algorithms, SSA, affine dependence, specialization, f32, a universal IR, an e-graph, a polyhedral library and an SMT solver. The core must be stated without saying what a program is, and it must run with an empty library.

1 · F27: a Tix pass in a plan loses its meaning gate found by A, B and C; F27 itself was misstated

The code path

Corrections found while tracing

Reading the four reviews in full against this page found six places where the page's first version overstated or misattributed. The wording above has been corrected; these notes record what changed and why.

  1. C's “BTA probe is not on Tix” (C's card, and the verified row “The solver runs a binding-time analysis on Tix”, C, D). C never claimed Tix. Its claim was that B1's analyses “bypass a solver that can already express them (probe 04)”↗, and its probe header says it encodes a dispatch loop. The qualification belongs to the row's attribution, not to C.
  2. D's “diff.ts listed as unused”. D's probe table lists ir/diff.ts among modules with zero names imported, which is true. Its layer assessment lists diff as held: “Keep: adapters, views, diff, correspondence.”↗
  3. “D's reconciliation of 2,021 against 1,774 failed.” D did not reconcile, and said so. It named two differences, and the first is the one probe 09 found: “probe 06 counts 1,774 on main, which has D1's loop fix merged and checks with fewer cases. I did not reconcile the two numbers”↗. Only the second reason, the case count, failed.
  4. “Tix passes run in plans and lose their gate”: B, C. A showed it too. Its P1 ran the async runner (same revision, no contract) and its P2 ran fork/chooseBest over Tix passes in the existing interpreter (A's walkthrough).
  5. Staged choice “resting on a single Claude review”. Two others propose it. A, an OpenAI review, marks its concept 7 evidenced: “A variant names its guard and fallback, required semantic obligations, and plan or code reference.”↗ D: “A plan that defers a choice to launch time is a plan with a guarded alternative”↗. What rests on C alone is the select(…, { stage }) strategy node.
  6. “24 claims probed (scripts 01–11)”. verification.md has 24 rows, and row 24 was checked by reading. 23 were probed: 19 held, 2 failed, and 2 are context (a timing, a consistency check).
