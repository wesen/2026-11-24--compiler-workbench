Tix is an index-notation tensor language built on the IR Workbench's v6 framework. Each stage was designed and implemented independently by every agent configuration from one brief, scored blind, and checked by hidden tests. Stage 1 built the language and two checked passes; stage 2 lowered it to CUDA on an NVIDIA GB10.

Stage 2: the twelve GPU backends

The three bit-exact backends round every addition and multiplication explicitly, so nothing fuses into FMA, and compute exp, log and tanh in double before rounding. An exhaustive check over all 2³² f32 inputs showed that construction equals the f32 meaning. The other nine use single-precision expf and tanhf and are about one unit in the last place off where those appear. Every backend checks itself only under tolerance.

How fast the generated CUDA is

Stage 2 fixed a naive mapping: one kernel per statement, one thread per output element, each reduction a sequential loop. The merged backend (IRWB-022-I) is several times slower than cuBLAS on the matrix multiplies and than one fused pass at the measured 244 GB/s on the row-wise programs. References were measured on the same GB10 with cuBLAS in strict FP32 math.

The creativity round

Four cells answer one open question: what compiler work would make Tix best in class? Each may search the web and run experiments on the GB10, and writes a ranked design document and a diary. Codex runs Sol and Astra at high effort; Opus and Fable run as Claude Code subagents at their default effort. All four get the same brief and the same two standing rules. All four sessions finished well inside their three hours. Two judges from different model families scored the designs blind, twice each, on ingenuity, creativity, scientific depth, evidence, correctness, grounding and padding.

How far these numbers go
  • In the creativity round, the first judging pass left out 21 result logs from three of the four tickets, by a packing bug that the second pass corrected. The scores shown include both passes; their differences are within the run-to-run spread given above.
  • Each configuration ran once. Opus and Fable have two stage-1 designs and one stage-1 implementation each, and did not run in stage 2.
  • The design judges were Claude subagents. Blinding hides the author's name but not the writing style, so the Claude designs' scores may carry a style preference.
  • Two judges scoring the same document differed by up to two fitness points, so gaps under about one point are noise.
  • Kernel times are single runs in fresh processes and differ from warm medians by up to two times.
  • Stage 1 counts all tensor source lines; stage 2 counts the lines each implementation added to the stage-1 base.
  • The two Claude stage-1 implementations pass 22 of 25 hidden tests because they forbid an index named like a tensor, a rule the brief left open. Both pass the variant suite that allows it.
